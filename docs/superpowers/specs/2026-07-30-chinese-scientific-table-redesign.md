# 多糖科研数据库中文化与列表改版设计

## 目标

在不改变原始科研数据模型的前提下，优化数据库列表的信息价值与中文使用体验：

- 删除公开数据库列表中的 `STRUCTURE` 和 `REVIEW` 两列。
- 新增“单糖组成”和“组成比例”两列。
- 将前台、后台及交互提示全部中文化。
- 采用清晰、克制、具有科研科技感的视觉风格。

## 范围

### 列表字段

“单糖组成”按以下优先级显示：

1. `monosaccharide_standardized`
2. 当标准化字段为空或仅含空白时，回退到 `monosaccharide_original`
3. 两者均为空时显示“未记录”

“组成比例”读取 `monosaccharide_ratio`，空值显示“未记录”。

列表不再展示 `structure_completeness` 和 `review_status`。这两个字段及其数据必须继续保留，并在记录详情页、数据字典和后台编辑表单中正常显示。

“单糖组成”在桌面端最多显示两行，超出部分省略；单元格使用原始完整文本作为悬停提示。组成比例保持紧凑、易比较的数字排版。

### 中文化

中文化覆盖全部面向用户的界面文本：

- 顶部导航、页面标题、副标题和说明
- 数据库筛选器、排序项、表头、按钮、链接和分页或结果提示
- 记录详情页和数据字典
- 数据质量页面
- 管理员登录、仪表盘、记录列表、新建与编辑页面
- 表单标签、占位文字、提交反馈、错误信息、空状态和无障碍文本

科研数据本身不翻译。英文名称、DOI、物种拉丁名、期刊名、英文文献标题和数据库中已有的英文实验信息保持原文。

日期使用中文区域格式；产品名称、页面语言元数据和浏览器标题同步改为中文。

## 视觉设计

整体采用明亮的科研工作台风格：

- 以白色和浅灰为主要背景，深灰用于正文。
- 青绿色作为主操作色，亮青色仅用于焦点、选中和数据强调。
- 使用清晰的细边框、稳定的表格网格、克制的阴影和紧凑的信息密度。
- 不使用大面积渐变、装饰性光球或营销式卡片堆叠。
- 表头强化层级，数据行增加轻微悬停反馈，链接和按钮具有明确的键盘焦点状态。
- 中文字体与英文、数字混排保持清晰，组成比例使用等宽数字特征。

表格继续放在自身的横向滚动容器中。桌面端稳定展示新增两列；窄屏允许表格内部横向滚动，不产生页面级横向溢出。

## 组件与数据流

- `RecordTable` 负责替换两列表头和单元格展示。
- 新增一个纯函数或复用现有数据工具，统一计算“单糖组成”的标准化字段优先与原始字段回退逻辑。
- `RecordFilters`、公共页面、详情组件、后台壳层和表单逐项替换为中文文案。
- 原始记录对象、Excel 导入结果、运行时存储格式和后台保存行为不改变。
- 搜索与筛选仍可使用结构完整度和审核状态；仅把相关界面标签翻译为中文。

## 异常与空值

- 空字符串、仅空白字符串、`null` 或 `undefined` 均视为缺失。
- 标准化组成缺失时必须回退到原始组成。
- 两个组成字段均缺失时显示“未记录”，不显示空白单元格。
- 长内容的悬停提示必须包含当前实际显示来源的完整值。

## 测试与验收

自动化测试至少覆盖：

- 标准化单糖组成优先显示。
- 标准化组成为空时回退到原始组成。
- 两个组成字段均为空时显示“未记录”。
- 数据库表格不再出现 `STRUCTURE` 和 `REVIEW` 表头。
- 数据库表格出现“单糖组成”和“组成比例”表头。
- 公开页面和后台关键界面不再残留英文操作文案。

完成后执行完整测试、代码检查和生产构建，并使用桌面与手机视口进行浏览器检查，确认：

- 列表列、回退逻辑和悬停完整文本正确。
- 公开页面和后台主要流程均为中文。
- 详情页与后台仍保留结构和审核数据。
- 表格无页面级横向溢出，文字不重叠，操作焦点清晰。

## 分工与审查

实施采用 Superpowers 的分工式开发：

1. 数据与测试角色：先建立字段回退和列表列变更的失败测试，再实现最小数据逻辑。
2. 界面角色：完成全站中文化、表格排版和科技感视觉调整，并做响应式检查。
3. 审查角色：独立核对需求覆盖、科研字段保留、测试结果和桌面/手机视觉表现。

每个实现阶段在进入下一阶段前单独检查差异与验证结果。最终审查发现的问题必须修复并重新验证后，才能进入推送和 Pull Request 流程。
