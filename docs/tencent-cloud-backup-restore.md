# 备份与恢复 Runbook

## 备份策略

- 上线前：停止写入，复制原始 Excel 和 SQLite 数据库到只读备份位置，并创建 PostgreSQL 云数据库手工快照；记录代码 commit、migration status、记录数和全库哈希。
- 每日：启用腾讯云 PostgreSQL 自动备份和时间点恢复，保留周期按科研数据管理要求配置；COS 开启版本控制或生命周期保护，禁止应用账号批量永久删除。
- 每月：由运维人员将最新备份恢复到隔离测试实例，通过部署文档中的受限 `systemd-run` 命令执行 `db:status`，完成记录数/42字段哈希核验、登录及附件抽样下载，并记录恢复演练结果。

## PostgreSQL 恢复演练

1. 禁止对生产库原地演练，创建隔离 VPC/测试实例并从指定快照恢复。
2. 将只针对该测试库的临时凭据写入 root 所有、权限 `600` 的独立 EnvironmentFile，通过部署文档中的受限 `systemd-run` 命令执行 `db:status`；hash 不一致立即停止。不得在当前 shell 中 source 环境文件。
3. 执行只读数据校验、772条基线核验（上线后按审计确认增量）、42字段哈希及关键关系数量检查。
4. 在测试应用验证 `/api/ready`、检索、用户登录、收藏、回收站和附件授权下载。
5. 记录 RTO、RPO、失败项并销毁临时凭据和实例。

## 故障恢复

先停止 systemd 应用避免继续写入，保存故障库快照和日志，再由负责人选择最近一致性恢复点。恢复到新实例后先核验 migration hash 和数据，再切换 CVM 环境变量并重启；不得直接覆盖唯一备份。若 PostgreSQL 迁移前需回退，可使用上线前 SQLite 快照只读核查，但生产恢复以已验证的 PostgreSQL 快照为准。
